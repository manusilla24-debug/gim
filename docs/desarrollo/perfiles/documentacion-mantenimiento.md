# Documentación y mantenimiento

## Ámbito y prioridad

Solo Registro de Fuerza. Lee AGENTS.md y respeta sus reglas y la petición actual.
Este perfil no autoriza ediciones, instalaciones ni publicaciones por sí mismo.
Si una instrucción del perfil contradice AGENTS.md, no la apliques y explica por qué.

## Objetivo

Explicar la aplicación con claridad y facilitar su mantenimiento sin añadir
herramientas ni reestructurar archivos fuera de la tarea.

## Comprobaciones

- Lee el código relevante antes de describir responsabilidades o comportamiento.
- Contrasta README, AGENTS.md, rutas y procedimientos; señala diferencias sin
  ampliar automáticamente una tarea a toda la documentación del proyecto.
- Explica copias, restauración, selección de atleta y límites de datos locales en español sencillo.
- No prometas sincronización, autenticación o recuperación que la aplicación no ofrece.
- Para cambios de comportamiento, estructura o uso, actualiza README según AGENTS.md.
- Mantén decisiones importantes junto a su contexto, sin imponer plantillas extensas.
- Revisa cambios acumulados cuando exista un problema concreto de divergencia.
- Prepara commits pequeños y comprueba exactamente sus archivos; no añadas
  exportaciones personales, `.vercel/`, archivos de herramientas o cambios ajenos.
- Una publicación en GitHub y un despliegue correcto de Vercel son verificaciones distintas.
- Mantén FUENTES.md y perfiles al cambiar referencias o responsabilidades;
  no actualices el catálogo externo automáticamente.

## Entrega y límites

Explica qué cambió, por qué y cómo se verificó para una persona sin conocimientos
técnicos. Enlaza los archivos relevantes. Distingue comandos ejecutados de ejemplos
documentados. No añadas generadores de documentación. Actualiza esta guía cuando
cambien estructura o procedimientos de mantenimiento.
